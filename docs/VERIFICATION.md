### Откуда взялось отсутствие шрифтов

Первый визуальный прогон дал расхождение 5,3–17,8% на **всех** страницах.
Причина: в `demosite.min.css` объявлено 9 `@font-face`, и браузер запрашивал
эти файлы, а зеркало отдавало 404. В репозитории лежал только один шрифт —
`Raleway-Extrabold-800.woff2`, единственный упомянутый в разметке через
`<link rel="preload">`. Итог: весь текст рисовался системным шрифтом вместо Jost.

**Побайтовая сверка этого увидеть не могла:** обход собирал ассеты из
атрибутов HTML, а девять шрифтов упоминаются только внутри CSS. Исправлено:
`verify_mirror.py` разбирает `url(...)` в CSS и обходит найденное. После
исправления обход находит 21 ассет вместо 12.

### Почему 5 страниц всё ещё расходятся

Все пять отличаются в **зоне контактов — встроенной карте Google**, и
недетерминизм доказан контрольным опытом: каждый сайт снят дважды и
сравнён с самим собой.

| Сравнение | Расхождение | Строки |
|---|---|---|
| зеркало vs **зеркало** | 454 px (0,0213%) | 1178–1537 |
| оригинал vs **оригинал** | 2908 px (0,1363%) | 1231–1538 |
| зеркало vs оригинал | 3428 px (0,1607%) | 1231–1539 |

Оригинал расходится **с самим собой** почти так же, как с зеркалом
(0,1363% против 0,1607%), и в тех же строках. Значит остаток — не свойство
зеркала, а недетерминированность стороннего виджета: карта грузится
асинхронно, и подписи вроде «Быстрый планшет», «Центр города» успевают
отрисоваться по-разному.

**Это не дефект зеркала** — подтверждено экспериментом, а не предположением.

## 4. Чем мы отличаемся от оригинала

### 4.1. URL со слэшем и без — оба отдают 200, как на оригинале

Оригинал (ASP.NET) отвечает 200 на обоих вариантах каждого продуктового URL.
Зеркало раньше отдавало не то — и в этом был пробел покрытия инструмента
(раздел 4.2).

| URL | Оригинал | Зеркало (было) | Зеркало (стало) |
|---|---|---|---|
| `/archive` и `/archive/` | 200 / 200 | 301 / 200 | **200 / 200** |
| `/GraphQL` и `/GraphQL/` | 200 / 200 | 301 / 200 | **200 / 200** |
| `/Angular` и `/Angular/` | 200 / 200 | 301 / 200 | **200 / 200** |
| `/React` и `/React/` | 200 / 200 | 301 / 200 | **200 / 200** |
| `/DPC.Impact` и `/DPC.Impact/` | 200 / 200 | 301 / 200 | **200 / 200** |
| `/DPC.PdfGenerator` и `/DPC.PdfGenerator/` | 200 / 200 | 301 / 200 | **200 / 200** |
| `/QP8` и `/QP8/` | 200 / 200 | 200 / **404** | **200 / 200** |
| `/QP8_PG` и `/QP8_PG/` | 200 / 200 | 200 / **404** | **200 / 200** |
| `/DPC` и `/DPC/` | 200 / 200 | 200 / **404** | **200 / 200** |
| `/Widgets` и `/Widgets/` | 200 / 200 | 200 / **404** | **200 / 200** |
| `/search` и `/search/` | 200 / 200 | 200 / **404** | **200 / 200** |
| `/QP79` и `/QP79/` | 200 / 200 | 200 / **404** | **200 / 200** |

**Почему ломалось.** Страницы разложены в сборке двумя разными способами:
шесть — файлами (`QP8.html`, `QP8_PG.html`, `DPC.html`, `Widgets.html`,
`search.html`, `QP79.html`), шесть — каталогами с `index.html` (`archive/`,
`GraphQL/`, `Angular/`, `React/`, `DPC.Impact/`, `DPC.PdfGenerator/`).
Стандартная цепочка `try_files $uri $uri.html $uri/ =404` из этого не может
выжать оба варианта:

- каталог без слэша (`/archive`) → nginx уводит редиректом **301** на `/archive/`;
- файл с каталоговым URL (`/DPC/`) → $uri = `DPC/` нет, $uri.html = `DPC/.html`
  нет, $uri/ = `DPC//` нет → **404**.

**Решение (владелец сайта, 2026-11-19).** «Надо чтобы работало и со / на
конце и без него: если в старом работает, то и в новом должно работать.»
Ранее (2026-10-05) здесь был зафиксирован противоположный выбор — 301 на
канонический адрес со слэшем; он отменён.

**Как сделано.** В `site/nginx/default.conf` появилось правило, которое
перечисляет все 12 продуктовых страниц и для обоих вариантов URL ищет
одноимённый `index.html`, затем одноимённый `.html`:

    location ~ ^/(?<page>archive|GraphQL|Angular|React|DPC\.Impact|DPC\.PdfGenerator|QP8|QP8_PG|DPC|Widgets|search|QP79)/?$ {
        try_files /$page/index.html /$page.html =404;
    }

Список закрытый — чтобы правило не перехватило ассеты (`/css/...`, `/js/...`,
`/fonts/...`).

**Побочный эффект, который тоже закрыт.** Прямые `.html`-пути на оригинале
не отдаются (`/QP8.html` → 404, `/index.html` → 404, `/archive/index.html` →
404), а зеркало хранит страницы файлами и отдавало их напрямую. Теперь блок
`.html` помечен 'internal' — внешние запросы дают 404, а внутренние
редиректы (`try_files`, `error_page 404 -> /404.html`) работают как прежде.
**Каталоги ассетов тоже приведены к оригиналу.** На `/css/`, `/js/`,
`/fonts/`, `/img/`, `/images/` оригинал отвечает 404 (ASP.NET их не знает),
а nginx на каталог без `index.html` отвечал бы 403 — добавлено явное правило
`return 404;`

**Что совпадает с оригиналом и осталось как есть:** `/favicon.ico` — 404 на
обоих (файла `favicon.ico` нет ни там, ни здесь). Эндпоинты форм
(`/DPC/Send`, `/QP8/Send`) на оригинале дают 405 на GET, в зеркале — 404:
форма в зеркале отправляется на formspree, поэтому свой обработчик не нужен
(за всё время — 3 запроса, от ботов).


**Проверено** на собранном образе: 12 страниц × 2 варианта = 24 URL, все 200;
прямые `.html` и пути с другим регистром — 404; ассеты — 200. Тест:
`site/tests/test_nginx_urls.py`.

### 4.2. Скрипт не проверял URL, на которые никто не ссылается

Обход идёт по ссылкам из разметки. Везде написано `/archive/`, `/Angular/` — со
слэшем, поэтому варианты без слэша в обход не попадали и «полное совпадение»
выглядело правдоподобно. Это был **пробел покрытия инструмента**, а не сайта.

**Пробел закрыт (2026-11-19).** Добавлен `site/tests/test_nginx_urls.py`:

- сверяет список страниц в правиле nginx с фактическими страницами сборки
  (`src/pages/`) — новая страница без записи в правиле снова получила бы 404;
- проверяет, что правило страниц стоит раньше блока `.html` (иначе внутренний
  редирект перехватит кеширование HTML);
- проверяет, что блок `.html` помечен 'internal';
- живьём в контейнере поднимает образ и требует 200 на обоих вариантах
  каждой страницы. Без docker тест помечается как **пропущенный**, а не
  пройденный, — прогон остаётся честным.
**Инструмент тоже стал устойчивее.** Обход делает три попытки на соединение и
берёт отдельный таймаут для оригинала (--original-timeout, по умолчанию 90 с):
старый ASP.NET-кластер отвечает медленно, и без этого обход обрывался, страницы
выпадали из сравнения, а отчёт показывал «расхождение по составу страниц» —
инструмент врал сам себе. Таймауты настраиваются: --timeout (зеркало, 20 с) и
--original-timeout (оригинал, 90 с).


### 4.3. Мы добавили то, чего нет на оригинале

| Файл | Оригинал | Зеркало |
|---|---|---|
| `/robots.txt` | **404** | 200, 77 Б |
| `/sitemap.xml` | **404** | 200, 1 315 Б, 13 URL |

не потеря точности: поисковикам теперь есть что кушать.

В зеркале они тоже 404: это содержание оригинала, а не поломка переноса.

```bash
    --original-ip 91.216.147.7
```

Код возврата `0` — расхождений нет, `1` — есть, `2` — ошибка запуска.

**Проверять имеет смысл, пока жив оригинал.** После выключения кластера
`91.216.147.7` сверка станет невозможна, и базы для сравнения больше не будет.
Скрипт сам на это укажет — упадёт с ошибкой обхода, а не покажет ложное
«полное совпадение».

Для быстрой ручной сверки одной страницы:

```bash
curl -s https://downloads.quantumart.ru/QP8 | sha256sum | cut -c1-16
# ожидается 689bab99ddc92c31
```
