### Откуда взялось отсутствие шрифтов

Первый визуальный прогон дал расхождение 5,3–17,8% на **всех** страницах.
Причина: в `demosite.min.css` объявлено 9 `@font-face`, и браузер запрашивал
эти файлы, а зеркало отдавало 404. В репозитории лежал только один шрифт —
`Raleway-Extrabold-800.woff2`, единственный упомянутый в разметке через
`<link rel="preload">`. Итог: весь текст рисовался системным шрифтом вместо Jost.

**Побайтовая сверка этого увидеть не могла:** обход собирал ассеты из
атрибутов HTML, а девять шрифтов упоминаются только внутри CSS. Исправлено:
`verify_mirror.py` разбирает `url(...)` в CSS и обходит найденное. После
исправления обход находит 21 ассет вместо 12.

### Почему 5 страниц всё ещё расходятся

Все пять отличаются в **зоне контактов — встроенной карте Google**, и
недетерминизм доказан контрольным опытом: каждый сайт снят дважды и
сравнён с самим собой.

| Сравнение | Расхождение | Строки |
|---|---|---|
| зеркало vs **зеркало** | 454 px (0,0213%) | 1178–1537 |
| оригинал vs **оригинал** | 2908 px (0,1363%) | 1231–1538 |
| зеркало vs оригинал | 3428 px (0,1607%) | 1231–1539 |

Оригинал расходится **с самим собой** почти так же, как с зеркалом
(0,1363% против 0,1607%), и в тех же строках. Значит остаток — не свойство
зеркала, а недетерминированность стороннего виджета: карта грузится
асинхронно, и подписи вроде «Быстрый планшет», «Центр города» успевают
отрисоваться по-разному.

**Это не дефект зеркала** — подтверждено экспериментом, а не предположением.

## 4. Чем мы отличаемся от оригинала

### 4.1. Каталоговые URL без завершающего слэша → 301 вместо 200 — ОСОЗНАННОЕ РЕШЕНИЕ

| URL | Оригинал | Зеркало |
|---|---|---|
| `/archive` | 200 | **301** |
| `/GraphQL` | 200 | **301** |
| `/Angular` | 200 | **301** |
| `/React` | 200 | **301** |
| `/DPC.Impact` | 200 | **301** |

Редирект ведёт на тот же путь со слэшем, в один шаг, без зацикливания:

```
/archive → 301 → /archive/ → 200
           финальный URL: https://downloads.quantumart.ru/archive/
           содержимое: sha256 babbe87b71d7c1ab — совпадает с эталоном
```

Заголовок `Location` **относительный** (`/archive/`), поэтому браузер строит
полный URL сам и сохраняет `https://` и наш домен. Это не декоративная
осторожность: контейнерный nginx стоит за TLS-терминирующим прокси и реальной
схемы не знает, поэтому абсолютный редирект он собрал бы как `http://` —
понижение с HTTPS. Чинится директивой `absolute_redirect off`.

**Это решение принято владельцем сайта осознанно, а не осталось по недосмотру
(2026-10-05).** Рассматривались два варианта:

| | Оригинал | Зеркало (выбрано) |
|---|---|---|
| `/archive` | 200 | 301 → `/archive/` |
| Последствие | один контент по двум URL, канонический адрес не определён | один канонический адрес, второй приводится к нему |

**Почему выбран редирект.** Два URL с одним контентом — это классическая
проблема дублирования: поисковик не может определить, какая из страниц
каноническая, ссылки разводятся по двум адресам, метрики считают переходы.
Редирект это устраняет. Для посетителя разницы нет — один локальный переход,
страница открывается с тем же содержимым.

**Почему не воспроизвести поведение оригинала.** Задача зеркала — отдать тот
же контент по тем же адресам, а не воспроизводить дефекты исходной реализации.
Отличие касается только HTTP-кода на адресах, на которые никто не ссылается
(в разметке везде вариант со слэшем).

**Как вернуть поведение оригинала, если понадобится.** Убрать стандартный
редирект nginx для каталогов — точечные правила вида
`location = /archive { try_files "" /archive/index.html; }` для каждого
каталогового URL. Тогда оба варианта будут отдавать 200. Изменение
локальное, содержимое сайта не затрагивает.

**Важно:** этот случай скриптом **не обнаружен** — см. следующий раздел.

### 4.2. Скрипт не проверяет URL, на которые никто не ссылается

Обход идёт по ссылкам из разметки. Везде написано `/archive/`, `/Angular/` — со
слэшем, поэтому варианты без слэша в обход не попадают и «полное совпадение»
выглядит правдоподобно. Это **пробел покрытия инструмента**, а не сайта.

Если для следующего проекта нужна честная картина, в скрипт стоит добавить
фазу «проверить варианты каждого каталогового URL без слэша» и сравнивать коды
ответа, а не только содержимое.

### 4.3. Мы добавили то, чего нет на оригинале

| Файл | Оригинал | Зеркало |
|---|---|---|
| `/robots.txt` | **404** | 200, 77 Б |
| `/sitemap.xml` | **404** | 200, 1 315 Б, 13 URL |

Оба генерируются `build.py` из списка страниц. На оригинале их не существует,
поэтому в разделе «Ассеты» они и не числились. Это сознательное улучшение, а
не потеря точности: поисковикам теперь есть что кушать.

### 4.4. Битые ссылки в текстах страниц воспроизведены как есть

В текстах страниц `Angular` и `React` есть ссылки вида

В зеркале они тоже 404: это содержание оригинала, а не поломка переноса.

## 5. Как перепроверить

```bash
cd site
python3 tools/verify_mirror.py \
    --live-url https://downloads.quantumart.ru \
    --original-url https://downloads.quantumart.ru \
    --original-host downloads.quantumart.ru \
    --original-ip 91.216.147.7
```

Код возврата `0` — расхождений нет, `1` — есть, `2` — ошибка запуска.

**Проверять имеет смысл, пока жив оригинал.** После выключения кластера
`91.216.147.7` сверка станет невозможна, и базы для сравнения больше не будет.
Скрипт сам на это укажет — упадёт с ошибкой обхода, а не покажет ложное
«полное совпадение».

Для быстрой ручной сверки одной страницы:

```bash
curl -s https://downloads.quantumart.ru/QP8 | sha256sum | cut -c1-16
# ожидается 689bab99ddc92c31
```
